# Scenario Framework | 플레이어가 사건을 촉발하고 NPC가 반응한다

**상태:** APPROVED CONCEPT을 바탕으로 정리한 **설계 규격(PROPOSED)**. 구현된 API나 씬 포맷이 아니다.
**적용 범위:** 장기 싱글 시나리오, 향후 협동 확장. 기존 v0.2.2 사용자 수용 장면을 원형으로 삼는다.

## 1. 장르적 계약

각 시나리오는 (1) 짜증나는 일상 마찰, (2) 자유로운 첫 행동, (3) 주변 NPC의 즉각적/연쇄 반응, (4) 더 큰 난동 및 신고/수색/대응, (5) 선택형 고유 특별 루트와 결과를 제공한다.

**고정 순서 퀘스트가 아니다.** 플레이어가 먼저 무언가를 던지거나, 평화롭게 돌아다니거나, 이미 사건이 커진 장소로 이동해도 시스템이 모순 없이 반응해야 한다. 시나리오 고유 초반 대화는 정황을 설정할 뿐 강제 시작 버튼이 아니다.

## 2. 모든 시나리오의 필수 5종 콘텐츠

1. **평상시 마찰(Ambient Friction):** 등장인물의 얄미운 대사·시선·소소한 행동, 관계와 공간 설명. 짧고 비반복적으로 제공.
2. **첫 돌발행동 트리거(Inciting Action):** 대표 상호작용 1개 이상(책상 쾅/계산대 내려치기/서류를 내던지기 등)과 대체 시작 행동을 정의.
3. **전용 NPC 연쇄 반응(Reaction Sequence):** 누가, 무엇을 보고/듣고, 어떤 순서/지연으로, 어떤 대사·몸짓·접근·회피를 하는가. 시야·거리·상태를 고려한다.
4. **사건 확대(World Response):** 목격/신고, 경비 수색, 경찰 대응 등 공통 행동·상태 머신에 시나리오 맥락을 연결.
5. **고유 선택형 특별 루트(Optional Special Scenario):** 맵·관계와 연결되는 발견/진입 조건, 최소 두 가지 결과 또는 실패 경로, 달성 기록 및 점수 효과. 개시를 강제하지 않는다.

## 3. 고정된 기준 사례: 회사원 첫 책상 내려치기

이미 구현된 첫 반응 순서와 감정 연출은 수용된 게임플레이 자산이므로 신규 설계가 바꾸면 안 된다.

| 단계 | 플레이어/NPC | 반응·대사 | 구현 상태 |
|---|---|---|---|
| 평상시 | 직원들이 일함 | 상사·동료의 짧은 얄미운 업무 대사 | 기존 구현 |
| 대표 트리거 | 플레이어가 책상 내려침(첫 B, 반복 A) | 소리와 책상 충격이 사건을 알림 | 기존 구현 |
| 즉각 반응 | 박 대리 | 깜짝 놀라며 "왜 그래?" | 기존 구현 |
| 확인 반응 | 김 팀장 | 가림막 너머 빼꼼, "뭐야 무슨 소리야?" | 기존 구현 |
| 추궁 반응 | 김 팀장 | "이게 무슨 짓이지?"라고 하며 가까이 접근·잔소리 | 기존 구현 |
| 다음 단계 | 주변 직원·경비·경찰 | 구경/회피/실제 제지/추가 대응 | 기존 기반 구현, 장기 확장 별도 |

**예외:** 책상을 치지 않고 곧바로 물건을 던지거나 NPC를 공격해도 게임이 진행되어야 한다. 이 경우 '책상을 친 뒤 왜 그래?'라는 대사는 억지로 끼워 넣지 않고, 해당 행동에 맞는 일반 놀람·항의·회피·목격 반응으로 분기한다. 사건이 발생하면 아직 재생되지 않은 평상시 대사는 취소한다.

## 4. 시나리오 Reaction Sequence 공통 작성 형식

각 NPC 반응마다 다음을 최소 기록한다.

| 필드 | 뜻 |
|---|---|
| `event_id` / `trigger` | 고유 ID / 감지할 플레이어 행동·세기·장소 |
| `context_conditions` | 사건 단계, 인물 생존/의식, 거리·가시성·청각, 이미 발생한 이벤트 여부 |
| `actor` / `targets` | 반응 주체와 바라보거나 말을 거는 상대(싱글·협동 모두 지원) |
| `priority` / `delay_window` | 다른 대사와 충돌 시 우선순위와 대략적 반응 순서 |
| `animation` / `dialogue` / `movement` | 고개 돌림·표정·빼꼼·접근·도주 등 실제 연출 |
| `effect` | 상황 변화(목격, 경고, 수색 시작 등). 실제 피해액을 무조건 증가시키지 않음 |
| `interrupt` / `fallback` | 피격·도주·대상 사라짐·다른 행동·경비 개입 시 취소/대체 |
| `once` / `reset` | 한 판에 한 번인지, 재시작 시 초기화되는지 |
| `coop_adaptation` | 누가 먼저 행동했는지, 두 사람 모두에게 말하는지, 호스트 권한 여부 |

**반응 시스템은 컷신 플레이어가 아니라 게임 상태 변화의 일부**로 설계한다. 한 대사를 다 듣기 전 행동해도 반응과 후속 상태는 일관되어야 한다.

## 5. 시나리오 제작 템플릿

- **시나리오 ID / 로그라인:** 어떤 역할의 누구에게 어떤 끔찍한 하루인가?
- **시작 장소/상태:** 초기 카메라, NPC 배치/업무, 바로 가능한 조작.
- **평상시 대사·몸짓:** 도입 마찰 3~5개 초안. 동일한 인물에게서 끊임없이 반복하지 않음.
- **대표 사건 트리거:** 처음 의도된 행동과 다른 행동으로 사건이 시작될 가능성을 함께 정의.
- **전용 연쇄 반응:** 3~5개 비트의 Reaction Sequence + 유효 조건/취소 규칙.
- **일반 대체 반응:** 공격·파손·물건 던지기·무행동/이탈 등에 대한 폴백.
- **공간 재사용:** 기본 소품/기물/NPC/경비/경찰 로직 재활용 여부.
- **신고와 대응:** 목격 주체·신고 애니메이션/음성·경비 출동/수색·경찰 등장 알림.
- **특별 루트:** 발견 조건, 활성/중단/실패/종결, 독특한 결과, 달성 기록.
- **플레이 종료 및 재시작:** 제압/이탈/목표 달성 뒤 정리할 상태 및 기록.
- **협동 변형(해당 시):** 플레이어별 반응, 공동 목표, 동기화 경계.
- **비용/위험/검증:** 재사용 자산, 신규 애니메이션, 제작 어려움, 검증 최소 절차.

## 6. 점수·피해액 규칙

기존 `docs/game-spec.md`의 피해액($) 장부를 유지한다. 특별 루트의 '고득점'은 **아직 점수 정책이 확정되지 않았다**. 다음 안을 비교 설계한다.

- **안 A:** 기존 피해액과 독립된 아케이드 점수/특별 루트 완료/칭호. UI 표시·저장 키를 분리해 기존 장부를 보존.
- **안 B:** 특별 루트 수행으로 실제 생기는 추가 기물 손실, 업무 중단, 대응 투입만 피해액에 계상. 임의의 루트 완료 보너스 달러 없음.
- **평가:** 플레이어가 특별 루트를 자연스럽게 탐색하는가, 한 행동 무한 반복으로 기록을 파밍하는가, 원래의 간결한 HUD를 훼손하는가.
- 게임 내 가상 손해액을 실제 법률·의료·인명 가치를 정확히 반영하는 수치로 오해시키지 않는다.

## 7. 싱글 경찰 연출과 협동 주의

- 플레이어 구상: 폭행·신고 → 경찰차 도착 → 잠깐 게임 정지 후 카메라가 경찰 하차를 비추고 "POLICE ARRIVED!" 자막을 띄움. 이는 **장기 설계 후보**, 기존 구현이 아니다.
- 싱글에서는 짧은 강제 카메라 연출을 실험할 수 있으나, 반복 출동마다 재생하지 않도록 우선순위를 둔다.
- 협동에서는 전역 일시정지가 다른 사람의 플레이를 방해할 수 있으므로, 비차단형 공통 이벤트 신호/카메라 인셋/사이렌 등을 별도 평가한다.
- 경찰 수색·층 이동·추적 및 상위 대응은 한 층의 기본 반응과 다른 기술 게이트로 분리한다.

## 8. 최소 품질 게이트 (설계 및 이후 플레이 검증)

1. **시작 장면:** 플레이어 입력이 허용된 상태에서 누가 누구를 짜증 나게 하는지 알아볼 수 있는가?
2. **대표 반응:** 책상 내려치기 등 대표 트리거 뒤 각 NPC 대사·몸짓·접근 순서가 맞는가?
3. **대체 행동:** 해당 트리거를 무시하고 공격/투척/이탈해도 스크립트가 멈추거나 뜬금없는 대사를 하지 않는가?
4. **인터럽트:** 피격/도주/상황 확대 후 예전 일상 대사가 뒤늦게 재생되지 않는가?
5. **재사용률:** 새 시나리오가 공통 물리·AI·대응 로직을 복제 없이 사용 가능한가?
6. **특별 루트:** 안 해도 정상 플레이 가능하고, 하더라도 반복할 가치/다른 결과가 있는가?
7. **점수:** 한 행동의 손실 중복 계산이나 임의의 보너스 피해액이 없는가?
8. **협동:** 동일 NPC를 두 명이 건드려도 반응/물리 권한/이벤트가 이중 실행되지 않는가?

자동 검사는 이벤트·점수·상태복구에 집중. 인간에게는 **도입+대표 트리거의 1회 짧은 플레이와 한 판 결과** 정도만 검수 요청한다.
