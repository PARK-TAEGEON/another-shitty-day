**예상 작업 순서에 대한 제안**이지 일정이나 자동 미래 실행 약속이 아니다.

## 에이전트 협업 프로토콜

- 구현자: 1개 milestone 단위로 코드를 수정하고, 소스·결과 캡처·검사 로그를 남긴다.
- 리뷰어: 동작이 아니라 성공했다고 주장한 내용을 실제 렌더/수치로 대조한다.
- 통합자: 결정 로그와 충돌 없이 메인에 합친다. 작업별 Git 브랜치와 PR을 사용하는 것은 GitHub 생성 후 시작한다.
- 사람: 대량 승인 대신 R1/R3/R5의 핵심 장면을 실제 눈과 손으로 판단한다. 심각한 오류가 있으면 특정 단계에서 재검수한다.

## 하지 않을 일

- 도면만 보고 “실제 모델 제작 완료”라고 보고하지 않는다.
- AI 생성 프리뷰를 그대로 3D 게임 모델로 취급하지 않는다.
- 물리 테스트장 성공 없이 5명 전체에 래그돌을 복제하지 않는다.
- 사무실 구조 A/B/C는 선택 전이므로 임의로 변경하지 않는다.

## 신규 병렬 트랙: 시나리오 설계와 수직 슬라이스 (2026-10-13)

이 트랙은 R1–R6 아트/래그돌 검증의 완료를 선언하거나 해당 제작을 중단시키지 않는다. Astra 설계는 **코드를 수정하지 않는 병렬 작업**이다.

| 단계 | 산출물 | 자동/기술 게이트 | 인간 검수 |
|---|---|---|---|
| S0 문서 설계 | 시나리오 규격 + 첫 행동 NPC 연쇄 반응 + 특별 루트 + 점수 정책 대안 | 구현/제안 혼동 없음, 기존 첫 책상 장면 및 피해액 장부 보존 | 주요 재미 방향만 1회 결정 |
| S1 사무실 도입 | 기존 책상 내려치기 장면을 골든 테스트로 삼아 폴백 반응 명세 검증 | 트리거 1회, 다른 행동, 인터럽트, 재시작과 대사 유실 | 30초 도입 장면 한 번 |
| S2 대응 확대 | 신고/경비 수색/경찰 도착의 최소 사무실 실험 | 수색 상태, 경로, 이벤트 중복 및 리셋 검사 | 짧은 자유 플레이 |
| S3 특별 루트 | 사장실 보너스 시나리오의 발견/분기/결과 | 기존 $ 피해액 불변성 또는 명시적 버전 분리, 중단/실패 처리 | 한 판의 재미·분기 평가 |
| S4 두 번째 시나리오 | 시장 도입·NPC·소품·반응 재사용 검증 | 공통 시스템 복제 없음, 기존 사무실 회귀 | 시장 1회 플레이 |
| M0 온라인 타당성 | 2인 동기화 실험 (본편 확정 아님) | 동일 NPC/래그돌/소품의 권한, 지연/중복 이벤트 확인 | 두 사람 짧은 동시 플레이 |

**출시 범위와 구현 순서는 미확정.** 싱글 컷신 정지는 온라인 게임에서 그대로 강제하지 않는다. 특정 시나리오를 구현하기 위해 기존 수용 장면이나 HUD를 무단 재설계하지 않는다.
