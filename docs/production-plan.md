# DESK BREAKER — 제작과 재개 지침

## 제작 흐름

작은 기능 묶음을 구현하고 실행한 뒤 검토한다. 실행 가능한 결과물과 확인된 한계를 함께 남긴다. 사용자는 매번 코드를 검수할 필요 없이 주요 플레이 검수에 참여한다.

| 단계 | 제작 결과 | 기술 확인 | 사용자 판단 |
|---|---|---|---|
| 실행 기반 | 이동·시점 조작, 테스트 공간, 실행·검사·빌드 절차 | 프로젝트 시작, 입력, 종료, 내보내기 가능 여부 | 필요 시 조작 환경 확인 |
| **M1 타격감** | 책상 내려치기·주먹·발차기·던지기, 집기와 NPC 반응 | 충돌·입력·집기 놓기·오류 로그 | 시원한가, 무게가 다른가, 주변 반응이 보이는가 |
| **M2 한 판** | 잔소리→소동→경비→경찰→제압→점수→재시작 | 상태 전환, 점수 중복, 종료 후 입력, 초기화 | 일이 커지는가, 지루한 구간이 있는가, 다시 하고 싶은가 |
| **M3 완제품** | 아트·소리·UI, 설정·최고 기록, 최종 패키지 | 저장, 반복 실행, 성능, 에디터 없는 실행 | 표현과 조작이 만족스러운가, 공개 가능한가 |

M1에서 전체 경찰 대응이나 모든 파손 효과를 완성할 필요는 없다. M2에서는 끝까지 플레이할 수 있어야 한다. M3에서는 기술 시연용 임시 표현과 최종 표현을 구분하여 정리한다.

### 수용된 M1 장면 — 도착 후 상사 잔소리(v0.1.3)

D015에서 사용자는 v0.1.2의 상사 이동이 자연스러워졌다고 평가하고, **다가온 상사 앞에서 가만히 있으면 손짓하며 따지듯 잔소리하는 반응**을 요청했다. 동료의 만족한 구도, 수용된 상사 접근·보행, 빼꼼 등장·첫 대사 타이밍·자막, 교정한 양손은 유지한다. 외형 최종 마감은 별도 후속 작업이다.

상사의 실제 도착·정지와 플레이어의 이동·행동 없는 대기를 시작 조건으로 연결한다. 마우스 시점 조작은 허용한다. 세 문장에 서로 다른 손짓·상체·표정을 연결하고, 이동·행동에는 현재 문장을 끊은 뒤 다음 미사용 문장으로 재개한다. 상사 피격·개입·종료·초기화에는 남은 반응을 취소한다.

대기 조건, 중단과 재개, 한 번만 진행되는 대사, 일시정지·초기화와 기존 반응의 유지는 기술 검사로 확인한다. 실제 게임 영상에서는 **도착 후 말이 시작되는 간격, 따지는 태도, 손짓과 자막의 연결, 발과 몸의 안정적인 정지**를 검수한다. 최종 결과와 남은 문제는 [현재 상태](current-status.md)에 기록한다.

D016에서 사용자가 이 장면까지 만족스럽다고 평가했다. 이후 변경은 이 흐름을 유지하는 확장으로 진행한다.

### 완료한 앞선 묶음 — v0.2.0 사무실·인물·누적 피해액

D017·D018의 사무실 확장과 누적 피해액, D019의 같은 부서 5명 중심 구성, D020의 **정 인턴 변경과 실제 패치 요청**을 게임 코드에 연결했다. 같은 부서는 5명, 타 부서는 2명이며 경비·경찰은 소동 단계에서 별도로 투입된다. 구체적인 대사·배치·가상 금액은 현재 제작값이고 이후 플레이 감각에 따라 조정한다.

| 함께 구현한 항목 | 실제 코드의 범위 |
|---|---|
| 같은 부서 5명 | 김 팀장·박 대리·이 사원·최 과장·정 인턴. 상사 포함, 플레이어 제외. 정 인턴은 서류 동작·주황색 출입증·아는 척하는 짧은 말투로 이 사원과 구분 |

| 경비의 실제 제지 | 짧은 경고 뒤 손바닥을 펴며 접근하고 진로를 막는다. 닿는 거리에서 밀기 동작의 접촉 시점에 버티기 감소. 실제 거리·장애물을 확인 |

| 평상시 업무와 말투 | 타이핑·서류 확인·복사·커피 휴식의 네 활동. 가까운 중심 배역의 미사용 대사를 한 번씩 표시하고 소동 이후 남은 일상 대사는 폐기 |
| 상황에 따른 반응 | 사건 위치·거리·시야 차단·소리 세기와 인물별 지연. 첫 반응·진행 중인 잔소리는 배경 대사보다 우선 |
| 물건의 실제 손상 상태 | 8종 집기의 금·기울어짐·꺼진 화면·빠진 키·벌어진 덮개·파손·흩어진 서류. 상태별 누적 수리/교체비와 기존 물리 충돌체를 연결 |
| 피해액과 별도 개입 | 대상·비용 항목별 차액만 합산. 기물·치료/수습·노동·대응 내역과 별도의 소동 강도. 경비 1명 → 경찰 1명 → 지원 경찰 1명까지 유한 투입 |
| HUD·결과·기록 | 원화 형식의 총액·이번 증가 원인·네 항목 결과. 제압 후 장부 고정, 새 판 초기화, 기존 정수 최고 기록과 분리한 화폐 기록 |

**연결한 구성:**

- `world.gd`가 네 구역과 인물을 배치하고, 근처 업무 대사·사건 위치·거리/가림막 필터·우선순위 대사를 연결한다. 기존 `opening_role`과 새 업무/성격 데이터를 분리해 수용된 첫 장면을 보존한다.
- `office_npc.gd`가 업무 중단·인물별 반응·타 부서 회피·경비 제지를 담당한다. 일반 직원의 업무 중단/복귀 불가 비용과 인물의 치료·수습 비용을 상태 전환에서 알린다. 경비는 일반 직원 업무 중단비를 중복 발생시키지 않는다.
- `prop.gd`가 손상·사용 불능의 모습과 누적 비용을 알린다. 평범한 집기/내려놓기와 초기 중력 낙하는 점수·소동을 만들지 않는다. 책상 충격으로 실제 깨진 집기는 비용만 추가하고, 한 번의 책상 입력을 여러 소동 사건으로 부풀리지 않는다.
- `social_damage.gd`가 항목별 누적액과 증가분을 계산한다. `main.gd`는 그 장부에서 HUD/결과를 읽고, 실제 사건의 소동 강도로 개입을 따로 판단한다. 출동비가 다시 출동을 만드는 경로는 없다.
- 기록 키는 `records/social_damage_krw_v1`이다. 제압 이후 장부는 고정되고, 새 판은 인물·집기·비용·업무·대사·출동 상태를 초기화한다.

**이번 묶음의 검증:**

1. 기존 첫 반응·상사 접근·잔소리 회귀 검사로 승인된 장면의 순서·중단·정지·재개를 확인한다. 새 인물·고정 집기가 상사 통로를 침범하지 않아야 한다.
2. NPC 회귀 검사로 업무 동작, 가까운/먼 사건, 굳음·구경·회피, 경비의 짧은 경고·도달 가능한 제지, 반복 대사·비용 방지를 확인한다.
3. 물건 회귀 검사로 실제 중력 낙하·일반 내려놓기의 무과금, 모니터 100,000 → 300,000원의 차액, 모든 집기 상한, 반복 착지 방지, 깨진 물건의 재투척을 확인한다.
4. 사회 피해액 회귀와 통합 smoke에서 항목별 차액·합계·개입 분리·실제 출동·종료 후 고정·재시작·기록 분리를 확인한다.
5. 실제 화면에서 인물 밀도·구역·기존 첫 장면·타 부서와 경비의 행동·손상 모습·자막과 금액 UI를 확인한다. 자동 통과가 미술 완성도나 재미의 승인인 것은 아니다.
6. 최종 코드를 Windows로 내보내고, EXE 내장 데이터만의 smoke와 실제 게임 검수 영상을 준비한다. 완료한 검사만 [현재 상태](current-status.md)에 기록하며 Windows에서 직접 실행하지 않았다면 그대로 남긴다.

**사용자 검수는 한 번의 플레이 묶음으로 준비한다.** 먼저 다섯 명과 정 인턴의 밀도·공간을 짧게 보고, 새 판에서 기존 첫 장면을 확인한 뒤 타 부서·경비 반응과 손상·피해액까지 이어서 본다. 가장 먼저 고칠 인원/배치·반응·타격감 한두 가지를 받아 다음 수정으로 연결한다. 최종 모델 마감, 관절별 래그돌, 무한 증원과 장기 생존 밸런스는 현재 완성 범위로 보고하지 않는다.

## 완료한 앞선 묶음 — v0.2.1 HUD 정리·외형 보강·구조안 비교

D021에 따라 좌상단 “누적 피해액”과 달러 총액을 중심으로 HUD를 정리한다. 사건 알림·상시 조작법·시간/최고기록·우상단 소동 박스·하단 버티기 바를 제거하고, 실제 대사 자막은 유지한다. 설정과 조작법은 탭으로 분리하며 기존 금액 수치를 유지한 달러 기록 키를 사용한다.

같은 부서 다섯 명의 눈·눈꺼풀·얼굴·헤어·의상 메시를 보강하되 기존 모션 피벗과 충돌체를 보존한다. 같은 카메라와 조명의 수정 전후 실제 렌더를 비교하고, 동료 눈 커짐·상사 빼꼼·접근·잔소리 제스처가 유지되는지 확인한다.

사무실 구조는 A 밀집형·B 중앙 복도형·C 순환형의 제안 도면으로 준비한다. 6개 업무석과 2명의 타 부서, 상사·경비 동선과 첫 시야를 같은 조건으로 보여준다. 사용자 선택 이후 해당 구조를 실제 맵으로 옮긴다. 비교도만으로 맵 적용을 완료했다고 보고하지 않는다.

이번 검사는 변경 위험에 맞춰 UI 상태·메뉴 접근·통화/기록 분리와 영향을 받는 기존 첫 장면에 집중한다. 물리 코드가 바뀌지 않은 손/물건 전체 검사를 형식적으로 반복하지 않는다. 최종 import·smoke·Windows export·내장 데이터 로딩과 실제 UI/인물 화면의 결과는 현재 상태와 새 빌드 기록에 남긴다.

## 현재 묶음 — v0.2.2 여성 직원 두 명과 후속 아트 제안

D022의 사용자 요청에 따라 이 사원과 정 인턴을 성인 여성 직원으로 변경했다. 두 배역의 선택과 정돈된 단발·묶은 머리의 구체적인 디자인은 제작 판단이다. 기존 말투·타이핑/서류 업무·반응, 정 인턴의 주황색 옷·출입증을 이어간다. 같은 부서 5명·타 부서 2명, 수용된 첫 장면, 조작과 달러 HUD·피해액·경비 대응은 유지한다.

**완료한 확인:** 실제 사무실에서 카메라만 옮겨 여성 배역이 정확히 두 명인 구성과 두 업무·기존 대사를 확인했다. 김 팀장·박 대리·최 과장의 같은 조건 전후 렌더 PNG는 바이트 단위로 동일하다. 최종 import·소스 smoke·Windows export·소스 없는 별도 폴더에서 Linux Godot의 EXE 내장 PCK smoke를 통과했다. 경고와 실행 명령은 [v0.2.2 빌드 기록](female-cast-build-report.json)에 남겼다.

이번에는 전체 회귀 검사·Windows 네이티브 실행·PowerShell·목표 PC 검사를 실행하지 않았다. v0.2.1의 다섯 회귀와 v0.2.0의 아홉 회귀는 당시 결과로 보존한다. 사용자 검수에서는 두 인물이 실제 거리에서 구분되고 기존 캐릭터들과 같은 풍자 만화형을 유지하는지 본다.

사용자가 요청한 [외형·그래픽 개선 방법](art-quality-plan.md)은 별도의 **후속 추천안**이다. 대표 캐릭터 한 명과 책상 한 구역의 조형·변형·표정·조명을 먼저 완성한 뒤 확대하는 순서를 제안한다. 해당 Blender 모델·새 리그·조명 재작업과 추가 게임 기능은 이번 빌드에 적용하지 않았으며, 사무실 A/B/C도 아직 선택 전이다. 실제 완료 범위와 전달 파일은 [현재 상태](current-status.md)를 따른다.

## 역할과 작업 경계

- **개발·통합 담당:** 게임 코드와 장면의 최종 통합, 실행 및 빌드.
- **검토 담당:** 요구사항과 실제 구현 비교, 재현 가능한 오류 확인, 검사 결과 검토.
- **독립 작업 담당:** 문서·대사·에셋 조사 등 충돌 위험이 낮은 작업.
- **사용자:** 비주얼과 타격감, 한 판의 재미, 최종 공개 여부 판단.

병렬 작업을 시작하기 전에 수정할 파일과 책임 범위를 정한다. 여러 에이전트가 같은 핵심 장면을 동시에 바꾸지 않는다. 별도 작업 결과를 합친 뒤에는 통합된 프로젝트를 다시 실행한다.

## 작업 한 묶음의 완료 조건

1. 무엇을 변경했는지 설명할 수 있다.
2. 실행·검사 명령과 결과를 남긴다.
3. 가능한 환경에서 실제 빌드를 실행한다.
4. 확인하지 못한 OS·화면·소리·동작을 별도로 밝힌다.
5. 재현되는 문제와 다음 작업을 남긴다.

빌드 파일을 생성한 것과 Windows에서 실제 실행한 것은 다른 결과다. 화면 없는 검사가 통과해도 타격감·UI·오디오 검수가 완료된 것은 아니다.

## 검사의 우선순위

핵심 위험은 스크립트 오류, 물리 충돌 불안정, 중복 점수, 제압 후 상태, 재시작 초기화다. 자동 검사는 이 위험에 집중한다. 표현의 작은 변경마다 구현을 그대로 반복하는 검사를 만들지 않는다.

성능 문제가 생기면 동시에 움직이는 물건·파편·NPC 수를 먼저 확인한다. 필요 이상의 복잡한 물리 효과를 추가하기 전에 기존 장면을 안정화한다.

## 대화나 담당 에이전트가 바뀔 때

1. 저장소 작업 규칙, 실행 안내, 이 문서, 결정 로그를 읽는다.
2. 현재 브랜치·변경 파일·최근 커밋을 확인한다. 다른 작업자의 변경을 덮어쓰지 않는다.
3. 마지막 완료 보고에서 실제 검증된 범위와 미완료 작업을 확인한다.
4. 프로젝트를 실행하거나, 실행을 막는 원인을 재현한다.
5. 현재 단계의 남은 작업부터 이어간다. 이미 정한 범위와 결정을 새로 만들지 않는다.

작업은 활성 세션에서 진행된다. 세션 종료 뒤 자동으로 계속 실행되거나 예약 없이 재개된다고 약속하지 않는다.
